### 内容梗概（本集要讲什么）
讲清 RNA-seq 从 reads 到 count 矩阵的由来、count/CPM/TPM 的区别，以及导入前的基因 ID 与样本表检查。

### 视觉与角色（必须遵守）
风格：日系科普动漫，角色「小研+博导酱」，深蓝科幻背景，数据图从生物画面过渡出现。

### 分镜要求（共 5 幕，按时间顺序制作）
**第 1 幕 0:00–0:40**
细胞 → mRNA → 测序 reads → 比对回基因组的动画。

**第 2 幕 0:40–1:30**
reads 落在基因上被计数 → 生成『基因×样本』count 矩阵。

**第 3 幕 1:30–2:30**
对比 count/CPM/TPM；红字强调『差异分析用原始 count』。

**第 4 幕 2:30–3:30**
count 矩阵列名 与 colData 行名 连线对齐。

**第 5 幕 3:30–4:00**
导入检查清单：行列方向 / 基因 ID 类型 / 分组匹配。

### 旁白全文（请严格覆盖，可微调口语化，不可删减科学要点）
RNA-seq 分析的第一步同样是搞清楚数据是什么。我们测的是细胞在某一刻表达的全部 mRNA，测序得到海量短 reads，再把它们比对回参考基因组或转录组，数一数每个基因上落了多少条 reads——这就是 count 矩阵：行是基因，列是样本，格子里是原始计数。

这里有个常被混淆的点：count、CPM、TPM、FPKM 的区别。原始 count 受测序深度和基因长度影响；CPM 校正了深度；TPM/FPKM 还校正了基因长度，便于在样本内比较不同基因。但请记住一条铁律：DESeq2、edgeR 这类差异分析工具，要求输入『原始 count』，因为它们的统计模型自己会做归一化。如果你喂进去已经是 TPM，结果就不可靠。

第二份文件是样本信息表 colData：每行一个样本，列是分组、批次、协变量。它的样本 ID（行名）必须和 count 矩阵的列名一一对应、顺序一致，这是 DESeq2 能正确建模的前提。

导入 EMP 前请确认三点：基因在行、样本在列；基因 ID 用的是哪种类型（Ensembl、Symbol 还是 Entrez），是否需要后续转换；colData 的分组无缺失且与列名匹配。基础打牢，差异分析才稳。

### 结尾 3 要点字幕卡（各停留 3 秒）
1. RNA-seq 数据是『基因×样本』的原始 count 矩阵
2. DESeq2/edgeR 必须用原始 count，不能用 TPM/FPKM
3. colData 的样本 ID 要与 count 列名完全对应

- [ ] 是否每 8–12 秒有镜头运动或新元素？
- [ ] 数据概念是否从生物学画面「过渡」到图表？
- [ ] 是否包含 1 段 EMP 软件画中画操作？
- [ ] 结尾是否显示 3 条 takeaway？

请按分镜输出：场景编号、时长、画面描述、角色动作、台词/旁白、字幕、转场方式。

- **禁止**：静态 bullet 列表、无实体的纯几何图标、与旁白无关的素材拼接、夸张表情包
