# 分组学流程编排、分析引导与论文数据检索

本地开发增量，2026-11-07。启动方式和 raw-count 执行合同见 [AI 组学工作台](AI_OMICS_WORKBENCH.md)。当前验证实例为 <http://127.0.0.1:18080/>；源码尚未推送 GitHub，也未部署到公共网站。

## 从编号或论文找数据

打开左侧“矩阵下载”，使用顶部统一输入框：

| 输入 | 行为 |
|---|---|
| `GSE60450, GSE305056`，或换行分隔 | 去重后逐个查询，最多 10 个 GEO，保留各自成功或失败结果 |
| DOI、`doi:...`、doi.org 链接 | 按 DOI 查询 PubMed，并核对返回记录的 DOI；选择论文后再读取摘要 |
| PMID、`PMID:25516281`、PubMed 文章链接 | 读取指定记录的题目、摘要和 DOI 元数据 |
| 论文题目 | 在 PubMed 检索；由使用者选择匹配论文 |
| 上传 PDF | 当前应用服务解析 PDF，提取字面出现的编号，记录页码 |

摘要/PDF 提取的 GSE **只是候选编号**，可能属于被引用的研究。点击“查询这些候选 GEO 的文件清单”后，才会查询 GEO；点击具体数据集，再在下方审核文件与下载计划。检索、候选识别、下载和分析是不同状态，有各自明确的操作反馈。多份数据集保持独立，不自动拼接矩阵或混合研究组别。

PDF 最大 15 MiB，只检查前 100 页、最多 100 个候选编号和 100 万提取字符；每批最多查询前 10 个候选 GSE，并提示如何分批。无 OCR，不能读取加密 PDF，不执行文中的指令。文件上传到当前应用服务；不会把 PDF 内容发送给模型或 PubMed。远程部署时，“当前应用服务”是部署服务器，不是用户浏览器所在电脑。解析子进程有 20 秒超时，Unix 有 CPU 限额，Linux 另有地址空间限额；macOS 不使用不受支持的 `RLIMIT_AS`。

当前统一入口的可下载目标是 GEO Series 补充文件。SRP/BioProject 等字面提及不会冒充 GSE；尚未实现 PRIDE、MetaboLights、受控数据库及任意出版社全文的统一下载。DOI/题目检索限于 PubMed 收录记录，未定位到论文或摘要未提及编号不表示没有公开数据。此时可上传含数据声明的 PDF，或直接输入 GEO。

“导出检索记录”保留请求类型、候选、来源和失败信息。它不包含模型生成的关联判断，也不证明文件已验证为 raw counts。文件名、后缀和整数值均不能单独证明数据尺度；下载后继续核对作者说明与样本信息。

## 为不同组学组合步骤

进入“AI 分析工作台”，先选择组学、输入类型和模板，再从步骤库添加、删除、上移/下移或拖动排序。每种组学的草稿分别保存在当前浏览器本地；切换中英文保留输入、步骤和参数。

| 类型 | 主要可选步骤 | 额外必需或条件依赖 |
|---|---|---|
| bulk RNA-seq | 归一化、PCA、DESeq2、热图、火山图、富集、WGCNA 计划 | PCA/热图需要归一化；DESeq2 需要 raw counts |
| 蛋白质组 | 过滤、缺失处理、归一化、PCA、差异、热图、通路 | 缺失处理可选，须先审核机制与处理决定 |
| 代谢组 | 过滤、缺失处理、归一化、PCA、差异、火山图、通路 | 同上，不自动填补或变换原始数据 |
| 16S 微生物组 | 过滤、分类汇总、稀释、多样性、差异丰度、组成图 | 稀释为按目的选用；计数方法不接受相对丰度 |
| 宏基因组功能矩阵 | 过滤、归一化、差异、富集、热图、关联计划 | 先审核功能尺度和样本设计 |
| ChIP-seq / CUT&RUN | 调峰、峰注释、motif、差异结合、RNA 联合 | 必须核对基因组版本；BAM 输入需要峰的步骤会加入调峰 |
| 临床 / 表型 | 基线表、系统临床统计、关联、预测设计计划 | 预测计划先加入数据泄漏与验证设计审核 |
| 多组学联合 | 分组学差异、关联、联合建模、通路计划 | 必须先核对跨组学样本对应 |

所有模板均保留“数据与来源”“样本与设计”“质量检查”“导出与复现”四类必需节点，导出位于最后。必需节点锁定；被后续步骤依赖的节点在其消费者移除前不能删除。添加步骤会补齐前置依赖，违反依赖的排序会回退并说明原因。这些是本工作台的输入/审核合同，不意味着所有组学必须采用同一种统计方法。

也可在选择组学后输入“代谢组做 PCA、差异分析和热图”或“临床基线三线表”，点击“生成分析流程”。该功能使用本地白名单关键词规则，为所选组学生成草稿并补齐依赖；不调用模型，不切换成其他组学，也不推断分组或参数。无法可靠解释的否定指令、复杂设计或输入类型冲突会明确提示用步骤库调整。原始计数 RNA-seq 继续使用既有本地计数提案接口。此功能不是自由语言理解或自动分析的完成证明。

每个节点另有能力标识：

- **工作台可执行**：原始计数 RNA-seq 的 QC、size-factor 归一化、PCA、DESeq2、高变基因热图。经过输入预检、计划审核及确认后，由现有 R 作业接口执行。
- **需在已有页面执行**：提供对应页面入口，仍需在该页面导入、设置、审核并运行。跳转不代表数据或结果已经传递，也不代表整条流程可自动运行。
- **仅编排 / 未连接执行**：可以规划与导出，尚无此编辑器的执行适配器。
- **必需审核 / 交付**：描述输入、设计、QC 或输出的人工核对要求；结构预检不会替代这些工作。

非原始计数流程，或加入尚未连接执行器的步骤后，“检查并准备流程”仅展示结构校验与蓝图，不启动整条分析。不能把结构通过的 `valid` 解释为数据通过、环境可用、方法合适或分析完成。TPM/FPKM 不能送入 raw-count 方法。蓝图格式为 `emp-workflow-editor-v1`，不接受自定义代码、未知步骤、重复步骤、错误参数和缺失依赖。

## 右侧分析助手

分析页默认展示引导：当前步骤、输入是否已选择、科学核对项、待审核步骤计划，以及模型/R 服务状态。数据“已选择”不等于“已验证”。临床三线表会提示分析单位、分组、变量类型、缺失及比较方法；不会把 RNA-seq 执行按钮混入临床流程。

主页面策略与助手子步骤同步。系统实现源码、自定义脚本及模型代码优化设置保留在“代码与模型（高级）”页签；参考源码可能含路由和请求变量，不宣称可以独立复制运行。助手可折叠，窄屏下也有可见的收起按钮。

本地规则引导自动启动；真实模型调用需要服务端配置和本次发送范围同意。问题框可用自然语言提问，但本机验证实例尚未配置模型。助手的请求只自动附加白名单页面/步骤名称，不自动附加脚本、矩阵、样本标签或文件。模型仅可通过受限工具提建议；建议进入工作台后仍需本地审核，不能直接触发 R 执行。指导记录可导出。

新增界面支持中英文同步，包含候选提醒、进度、步骤、参数及服务状态；原始论文标题、文件名和原始证据不翻译。其他语言使用项目现有回退，不宣称完整支持所有长尾语言。
